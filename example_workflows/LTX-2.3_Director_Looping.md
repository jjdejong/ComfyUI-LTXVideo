# LTX-2.3 Director Looping

Two-pass AV I2V **looping** workflow driven by a WhatDreamsCost **LTX Director** timeline
through the **LTX Looping Bridge** node. It's the `LTX-2.3_Two_Pass_I2V_Looping` graph with
the prompt machinery, the reference scheduling, **and the separate timing node** collapsed
into Director + the bridge.

Generated by `transform_to_director_looping.py` (re-run to regenerate from the base
workflow). Requires the `LTXLoopingBridge` node (in `WhatDreamsCost-ComfyUI`), the Director
output patch (below), and a ComfyUI restart.

**Requires the Director output patch.** `ltx_director.py` is patched to expose three extra
passthrough outputs — `local_prompts`, `segment_lengths`, `global_prompt` — plus it already
outputs `frame_rate`. The bridge and the rest of the graph wire directly from these. The
patch is additive (appended outputs don't shift existing links). Caveat: it edits a tracked
third-party file, so a `git pull` in `WhatDreamsCost-ComfyUI` may revert it (good upstream-PR
candidate).

## Two-node control surface

Everything interdependent lives in exactly one of two nodes:

```
LTXDirector (authored in its timeline UI)            LTX Looping Bridge
  • total duration (timeline length)                   • temporal_tile_size  (widget)
  • fps           ── frame_rate out ──► fps bus         • temporal_overlap    (widget)
  • global prompt ── global_prompt out ─► bus           ── emits ──►
  • per-segment prompts ─► local_prompts/segment_lengths   temporal_tile_size / overlap ─► both samplers
  • keyframes     ─► guide_data ─► bridge                  frame_count ─► empty video+audio latent shells
  • frame-0 image = a keyframe @ frame 0                   per_tile_conditionings ─► samplers (opt_positive)
  • positive out  ─► guider base positive                  cond_images / cond_image_indices ─► samplers
                                                           start_image (= cond_images[0]) ─► GetImageSize (dims)
                                                                                          └► VAEEncode (identity anchor)
```

- **Director owns** duration, fps, global prompt, per-tile prompts, keyframes. (Its
  `duration_frames`/`frame_rate` are JS-timeline-owned widgets and can't be driven by links —
  so Director is necessarily the source for these.)
- **The bridge owns** tile size + overlap (its own widgets), and **derives `frame_count`**
  (8n+1) from the Director timeline — so the empty latent shells and both sampler stages get
  their length/tiling from one place. No separate `LTXVLoopingReferenceSchedule` node.

The **plain** model (post-LoRA, node 25) feeds the samplers — *not* Director's
prompt-relay-patched `model` output. See the project `CLAUDE.md` for why.

## Before running

1. **Author the Director timeline**: set the total duration, fps, and global prompt on the
   Director node; place one text segment per intended tile (its position picks the tile);
   place keyframe images, **including the start frame as a keyframe at frame 0** (that's the
   I2V first frame now — the dedicated I2V-cond nodes were removed). The reference image is
   entered **only here** — the bridge's `start_image` output (= the earliest keyframe,
   `cond_images[0]`) feeds both the output-dimension math (`GetImageSize`) and the
   negative-index identity anchor (`VAEEncode`), so there's no separate `LoadImage`.
2. **Set `temporal_tile_size` / `temporal_overlap`** on the bridge (default 240 / 64). These
   are now the single source — they feed both samplers and the bridge's own tile math.

## What was kept vs. removed

* **Kept:** bus-driven `EmptyLTXVLatentVideo` + `LTXVEmptyLatentAudio` shells (now sized by
  the bridge's `frame_count`), both guiders/samplers, 2× spatial upscale, tiled VAE decode,
  audio decode, `VHS_VideoCombine`, and `GetImageSize` (dims) + `LTXVPreprocess` → `VAEEncode`
  (identity anchor) — now fed from `bridge.start_image`.
* **Removed:** `MultiPromptProvider` + snippet/concat/merge chains; late-reference
  `LoadImage`/`ImageBatch`; **`LTXVLoopingReferenceSchedule`** (timing → bridge); the **fps
  primitive** (→ Director); the **Global Positive Prompt primitive** (→ Director); the
  **Global-prompt fallback encode** (guider positive → `Director.positive`); the
  **Stage-1/2 I2V-cond nodes** (frame-0 → Director keyframe); and the **reference `LoadImage`**
  (start frame → `bridge.start_image` = `cond_images[0]`).

## Optional: Director-driven custom audio

Director also outputs `audio_latent` / `combined_audio`. To use imported timeline audio:
delete `LTXVEmptyLatentAudio`, wire `LTXDirector.audio_latent` → `Stage 1 AV Concat` audio
input, enable `use_custom_audio`, and keep the Director timeline duration matching the clip.
